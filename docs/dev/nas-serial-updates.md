# NAS 连载续更边界

当前 NAS 下载 API 传输整本文件，上传接受整包和重复处理策略。已有 `client_source_key`、`chapter_count` 和 `replace_book_id` 字段，但不是章节清单、按章数据接口或带版本条件的提交接口。仅章节总数增加不能证明旧内容不变，不能用它触发自动覆盖。

- 新下载按 NAS 来源、书籍 ID 和实收内容的 SHA-256 版本隔离，放进应用管理的 `filesDir/nas-books`。相同来源、书籍、文件名及内容重用原路径和书架记录；不同内容未验证能安全合并时另存，不替换旧版。升级不迁移既有下载文件，也不按文件名绑定旧书。同名仅用于展示。由于保存位置是应用私有目录，卸载会删除这些下载。
- 历史重试绑定原 NAS 地址的不可逆标识，不保存连接凭据。缺少标识的旧记录不能自动重试，请从当前书库重新选择原书。
- 对书源漫画，后台只接受旧目录身份和索引完整保留的追加；检测到插章、重排或替换时提示打开目录显式处理，不改当前阅读窗口。

## 后续协议需要验证

1. 按稳定书籍 ID 读清单：版本、章节 ID、顺序、每章内容校验值。客户端旧版必须是新版的完整前缀才能自动续更。
2. 上传只发送缺失章节；服务端按读取时的版本提交。若期间另一设备做了更新，服务器拒绝提交并让客户端重新对比，不能降级为 overwrite。
3. 下载只取缺章；先写临时版本并完整校验，再提交到原来的本机书架身份。确认失败或中途取消，不动旧版文件、阅读进度、书签及分组。
4. 不支持按章接口的服务端仍可整包传输，但只能在能证明旧章节内容不变时更新既有版本；不明格式及旧章冲突须另存或让用户确认替换，不能把整传称为增量。

## 现有手动覆盖（不是连载续更）

漫画上传确认时保存目标书籍 ID 和服务端报告的整包 SHA-256。队列执行、历史重试和整包发送前都会核对原版本；没有原版本（包括以前入队的覆盖任务）时，要求重新确认，不能用最新版本替旧任务重新授权。客户端复查与服务端写入之间仍有并发窗口；现有后端不提供原子的版本条件，复查不能作为并发写入保证。
